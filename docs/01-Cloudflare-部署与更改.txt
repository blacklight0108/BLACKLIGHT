BLACKLIGHT · Cloudflare Pages 部署与更改说明
========================================================
最后更新：2026-10-25（UTC）
适用：用「BLACKLIGHT-网页文件.zip」部署到 Cloudflare Pages


一、先搞清楚这两个东西的关系
------------------------------------------------
你手上会有两个包，别弄混：

  BLACKLIGHT-网页文件.zip   → 传到 Cloudflare，网站长什么样就是它决定
  BLACKLIGHT-源码与自动更新.zip → 传到 GitHub，负责每 6 小时自动抓 B 站更新并重新部署

只传 Cloudflare：网站能开，但 UP 主投稿不会自己变新。
只传 GitHub：Cloudflare 那边会收到新版本，但前提是 Secrets/Variable 都配好了。
两个都传好：以后内容自己更新，你基本不用管。

网站线上预览（我这边也部署了一份给你看效果）：
  https://orbitalnoise-qnwk.web.zaka.live

你自己的 Cloudflare 地址（部署完就是它）：
  https://你的项目名.pages.dev
  项目名现在是 orbitalnoise → https://orbitalnoise.pages.dev


二、一次性准备（只做一次）
------------------------------------------------
1. 打开 https://dash.cloudflare.com 并登录。
2. 左侧点「Workers 和 Pages」（英文界面是 Workers & Pages）。
3. 确认里面能看到你的项目。项目名就是地址里那一段，例如 orbitalnoise。
4. 手机上建议装 Cloudflare App 或者直接用手机浏览器登录，一样能部署。
5. 账号安全：右上角头像 → My Profile → Authentication → 打开 Two-Factor（两步验证）。
   开了之后每次登录要输一次验证码，但别人就算知道密码也进不来。


三、正式部署（拖拽，最常用）
------------------------------------------------
1. 把 BLACKLIGHT-网页文件.zip 解压。
   解压出来应该直接看到这些，而不是再套一层文件夹：
     index.html
     assets/（里面一个 .js 一个 .css）
     avatars/（19 张头像）
     data/updates.json
     content.json
     _headers
     robots.txt
     favicon.ico / favicon.png / apple-touch-icon.png / blacklight-mark.png
     uploads/（空文件夹，留给你放自己的图）
2. Cloudflare 后台 → Workers 和 Pages → 点你的项目 → 上方切到「Deployments」标签。
3. 点右侧「Create new deployment」（也可以点 Create deployment）。
4. 选择「Upload assets」（上传资源），不是「Connect to Git」。
5. 把上面那些文件和文件夹**全选**，一起拖进虚线框里。
   ⚠️ 拖的是「里面的内容」，不是把最外层文件夹整个拖进去。
     拖错的表现：网站打开是 404 或者一片空白。
     判断方法：上传列表里第一层就应该看到 index.html，看到的是文件夹名就删掉重拖。
6. 点「Deploy site」（或 Deploy）。等 10 到 30 秒，出现绿色的成功提示。
7. 点它给的链接打开，看到黑色标题 BLACKLIGHT、米白底、闪电标，就成功了。


四、部署完必须核对的 5 件事
------------------------------------------------
1. 浏览器标签页上的小图标是那道闪电（不是地球或空白）。
2. 顶部写着 BLACKLIGHT，一行显示、没有折行。
3. 往下能看到五个板块：01 专辑 / 02 雷达 / 03 文章 / 04 图片 / 05 游戏。
4. 雷达板块标题右边有一行小字：同步 2026-10-25 12:15 UTC ——说明抓取数据加载到了。
5. 两个小游戏能玩（点色块记忆、点方块测反应）。
6. 手机上打开一遍：不要横向拖动、不要有字被切掉。

如果第 4 条没有时间、卡片是空的，先别急，看第九节「常见坑」。


五、日常要改东西，走哪条路
------------------------------------------------
分三种情况，对号入座：

【情况 A】只改文字内容：加专辑、加文章、加图片、换 UP 主
  → 只改 content.json（和往 uploads / avatars 放图），改完可以直接拖拽重新部署（第八节）。
  → 具体怎么改，看《03-网站内容与日常维护.txt》。

【情况 B】改外观：颜色、字、板块顺序、游戏逻辑
  → 这些写在代码里，content.json 改不了。需要改源码 → 重新构建 → 得到新的 dist 文件 → 再拖拽部署。
  → 也可以在 GitHub 那边改完推上去，让它自动构建部署，这样 Cloudflare 完全不用手动碰。

【情况 C】只想让 B 站投稿自动更新
  → 什么都别在 Cloudflare 做，去配 GitHub（看《02-GitHub-自动更新-部署与更改.txt》）。
  → Cloudflare 纯静态托管不会自己跑定时脚本——这点很重要，别指望它自己更新。


六、Cloudflare 里几个按钮是干什么的
------------------------------------------------
Deployments（部署记录）
  每一次上传都留一条记录，带时间。点任意一条右边的「…」→ Rollback，
  就把网站退回那一次的样子。改坏了不用慌，退回上一版 30 秒的事。

Custom domains（自定义域名）
  现在是 你的项目名.pages.dev，免费的。
  以后买了域名（比如 blacklight.com），在这里点 Set up a custom domain，
  按提示去域名商加一条 CNAME，SSL 证书 Cloudflare 自动签，不用花钱。

Settings（设置）
  · 改项目名：注意！改了以后网址会变，GitHub 里的 CF_PROJECT_NAME 必须同步改，
    否则自动部署会报「找不到项目」。
  · 删除项目：不可恢复，删之前先确认 GitHub 那边的配置要不要留。

Functions / KV 之类
  这个站是纯静态，全部用不到，不用碰。


七、缓存与响应头（这次新加的）
------------------------------------------------
网页包里有一个 _headers 文件，Cloudflare 会自动读它，你不用做任何操作。
它的作用：
  · assets/ 里的 js 和 css 长期缓存（文件名带哈希，改了会自动换名，不会看到旧版）
  · content.json 不缓存 → 你改完内容，用户刷新就能看到新的
  · data/updates.json 缓存 5 分钟 → 抓取更新后最多 5 分钟全站生效
  · 头像和上传的图片缓存 7 天 → 打开更快
  · 顺带关了 MIME 嗅探、限定了 Referrer，安全一点

注意：如果你在某台设备上看到的是旧版，先按 Ctrl+F5（Mac 是 Cmd+Shift+R）强制刷新。


八、拖拽更新的完整动作（建议收藏这段）
------------------------------------------------
1. 改好文件（比如往 content.json 里加了一张专辑）。
2. 打开 Cloudflare → 你的项目 → Deployments → Create new deployment → Upload assets。
3. 全选新文件拖进去 → Deploy。
4. 打开网站，Ctrl+F5 强刷，确认改的地方出来了。
5. 如果不对：Deployments 里找到上一次成功的记录 → Rollback，先恢复，再慢慢排查。

小技巧：拖拽是「整站替换」，不是「增量更新」。
  所以要传的是完整的一套文件，不是只传改过的那一个文件。


九、常见坑（新手最容易踩的 8 个）
------------------------------------------------
1. 打开是 404 / 空白
   → 十有八九是套了一层文件夹。列表第一层必须是 index.html。
2. 页面能开但没样式（一片黑字白底）
   → assets 文件夹没传上去，或者它被改名了。assets 必须和 index.html 同级。
3. 图标还是旧的地球
   → 浏览器缓存。Ctrl+F5；手机端把标签页关掉重开。
4. 雷达板块没有投稿、也没有「同步 … UTC」
   → data/updates.json 没传，或者路径不对。它在 data 文件夹里，外面要有一层 data。
5. 改了 content.json 但网站没变
   → 三种可能：没重新部署 / 拖着缓存 / JSON 写错导致整份没读进来（页面会退回默认空内容）。
     验证 JSON 有没有写错：把内容粘到 https://jsonlint.com 点 Validate，绿了才算对。
6. 中文文件名图片显示不出来
   → 图片一律用英文名 + 下划线，别用中文、别用空格。
7. 手机上看右边被切掉
   → 通常是加了超宽的图片或表格。图片用 max-width:100% 的容器放（本站已有），
     自己加内容时别写死 width="1200"。
8. 部署成功了但自动更新没生效
   → Cloudflare 拖拽部署和 GitHub 自动更新是两套入口，最后一次部署决定线上是哪一版。
     如果你手动拖过一个旧包，它会覆盖自动部署的成果。想稳定自动更新就别再手动拖。


十、快速自检清单（每次部署完扫一眼）
------------------------------------------------
[ ] 网址能打开，200
[ ] 标题 BLACKLIGHT 一行显示
[ ] 闪电图标正常
[ ] 五个板块都在
[ ] 雷达有「同步 … UTC」和投稿条目
[ ] 手机端无横向滚动
[ ] content.json 里没有中文逗号、没有多余逗号
[ ] 传的是完整文件，不是单个改动文件


附：本版本相对上一版改了什么
------------------------------------------------
1. 时间全部统一成 UTC：抓取脚本写出 2026-10-25T12:15:35Z，页面显示「同步 … UTC」，
   列表里的日期也按 UTC 换算，任何人任何设备看到的都一样。
2. 新增 _headers：静态资源长期缓存、内容文件不缓存、附带三条安全响应头。
3. 新增 robots.txt：允许搜索引擎正常收录。
4. 首页补了分享预览信息（发到聊天软件里会显示标题和闪电图）。
5. 图标声明补全（.ico 和 .png 都声明，老浏览器也能认）。
6. 抓取脚本加了失败重试（两个接口都抽风时会再整体试一次），19 个频道更不容易掉数据。
7. 删掉了工程里的临时文件（旧备份、模板说明、构建缓存），包更干净。
